# Input Modalities Design Spec

**Date:** 2026-09-20
**Status:** Approved for implementation
**Approach:** B — Decompose first, then build

## Overview

This spec adds six new capability areas to the Ursly web app, extending the core product identity (human gateway, human interface, emotion detector, non-verbal realtime, model aggregator). Each capability is built as a single-responsibility component that plugs into the existing Workspace orchestration layer.

### Capability Summary

1. **Quick Toggles + Video Overlay** — One-tap voice/camera toggles, semi-transparent video layer
2. **Keyboard Fallback** — Settings-only text input with slash commands and real-time action suggestions
3. **Non-Verbal Tracking** — Real-time body signal tracking with color-coded emotional overlay and session log
4. **Document Upload + Gesture File Navigation** — Voice-triggered upload, dual-layer file system, tree-spatial gesture navigation
5. **Error Handling + User Feedback UI** — Unified feedback bus with brand-compliant visual treatment
6. **Language-Specific Voice Commands + Settings Reorganization** — Localized command dictionary, reorganized settings, full testing strategy

## Section 1: Quick Toggles + Video Overlay

### Quick Voice Toggle

A single outlined icon button (mic icon) positioned on the workspace edge. One tap toggles voice on/off. When off, the `SpeechRecognition` instance stops and the mic visual indicator dims. State persists across the session.

Replaces the current Start/Stop button in `SenseControls` with a simpler toggle pattern.

### Video Preset (Settings)

Settings gets a "Camera" card with a single toggle: "Video overlay". When enabled, a `<video>` element renders as a semi-transparent layer over the workspace content at 15-20% opacity. Content remains fully readable. The camera feed is local-only, never sent anywhere (same as current motion system).

### Layer Stack (bottom to top)

```
z-index layers:
  1. Content (conversation, document, YouTube)
  2. Video overlay (15% opacity, camera feed)
  3. Motion gesture visual layer (optional, toggleable)
  4. Menu overlay (settings, file browser)
  5. Quick toggles (always accessible, floating)
```

### Quick Toggle Bar

Two floating outlined icon buttons (mic + camera) at a workspace edge. Always visible regardless of screen state. Icon-only with aria labels. Tap = instant toggle, no confirmation dialog.

### Component Decomposition

- `QuickToggleBar` — renders the two toggle buttons, manages visual state
- `VideoOverlay` — renders the `<video>` element with opacity, handles camera stream
- Both receive state from `useVoice` and `useMotion` hooks (extracted from Workspace)

## Section 2: Keyboard Fallback Mode

### Activation

A toggle in settings under a "Keyboard" card: "Enable keyboard input". Off by default. When enabled, a text composer appears at the bottom of the workspace. It coexists with voice/motion — no mode switching required.

### Slash Commands

The composer accepts free text (sent to AI) and recognizes slash commands mapped to voice actions:

| Command | Action | Equivalent voice |
|---------|--------|-----------------|
| `/upload` | Open file upload | "upload" |
| `/summarize` | Summarize current source | "summarize" |
| `/back` | Go back | "back" |
| `/youtube <url>` | Load YouTube source | "youtube" |
| `/search <query>` | Search within source | "search" |
| `/clear` | Reset conversation | "stop" |
| `/settings` | Open settings | — |
| `/files` | Open file browser | "open" |

Typing `/` shows an inline autocomplete dropdown. Commands use `/` prefix in all languages; descriptions show in the active language.

### Real-Time Action Suggestions

A suggestion strip below the composer (or floating near it when keyboard is off) shows context-aware actions:

- User loads a PDF → suggestions: `/summarize`, `/ask`, `/search`
- User is in conversation → suggestions: `/back`, `/youtube`, `/upload`
- User says "upload" via voice → suggestion strip shows file browser shortcut
- User idle 10s → suggestions fade out

The strip shows 2-3 contextual actions as outlined chips (tap to execute). Works with voice active too — user can tap a chip or say the command word.

Suggestions generated by a rule engine in `packages/core/src/domain/actionSuggestions.ts`. No AI call needed. Rules based on: current source type, conversation state, last action, time since last interaction.

### Behavior Rules

- When keyboard is enabled, voice stays on by default. Both active simultaneously.
- Sending text does NOT trigger the echo guard.
- Keyboard toggle is in settings only — no quick toggle on main UI.
- If voice is off AND keyboard is off, user sees a prompt: "Enable voice or keyboard to interact."

### Accessibility

- Tab focus order: quick toggles → content → composer → menu
- Enter sends, Shift+Enter for newline
- Escape closes slash autocomplete first, then closes composer

### Component Decomposition

- `KeyboardComposer` — text input with slash command parsing
- `SuggestionStrip` — context-aware action chips
- `useKeyboardMode` hook — manages keyboard state, slash command routing

## Section 3: Non-Verbal Tracking System

### Real-Time Layer

`MotionActions` frame-differencing pipeline extends with a `NonVerbalTracker` port. Every gesture, gaze direction, movement energy, and posture change emits an event into a shared event bus. Runs alongside the existing gesture recognizer.

### Tracked Signals

- Gesture type + energy + duration (already captured)
- Gaze position + dwell time (already captured via `onGazeUpdate`)
- Movement energy level (brightness delta sum per frame)
- Distance estimate (face/body size in frame — closer = larger blob)
- Detected mood from voice tone (already in `express_mood`)

### Color Overlay

The video overlay and LivingLogo orb shift color based on dominant non-verbal signal:

| Signal | Color | Behavior |
|--------|-------|----------|
| Calm | Blue | Slow pulse |
| High energy movement | Orange | Fast pulse |
| Close proximity | Warm tones | — |
| Distance/far | Cool tones | — |
| Frustrated mood (voice) | Red | — |
| Curious | Green/cyan | — |

Colors blend smoothly (600ms transitions). User sees their own state reflected without reading text.

### Distance Indicator

Distance estimated from camera based on face/body blob size. Shown as a subtle ring around the video overlay:

- Close (< 50cm): tight ring, warm color
- Medium (50-100cm): normal ring
- Far (> 100cm): expanded ring, cool color, lower recognition confidence

### Session Log

`NonVerbalLog` component accessible from settings. Scrollable list:

```
14:32:01  Swipe right (energy: 0.42)  → Next question
14:32:15  Hold 1.2s (energy: 0.18)    → Ask action
14:33:02  Gaze center 3.4s            → Selected "Summary"
14:33:45  Movement spike (0.61)       → Mood: frustrated
```

Stored in-memory during the session. Architecture supports persistence later via port + adapter pattern.

### Component Decomposition

- `NonVerbalTracker` (port) — emits tracking events
- `NonVerbalTrackerAdapter` — wraps existing MotionActions frame pipeline
- `ColorOverlay` — maps signals to colors, renders on video layer + orb
- `DistanceRing` — renders distance indicator around video overlay
- `NonVerbalLog` — session log viewer in settings
- `useNonVerbalTracking` hook — manages tracker lifecycle, event bus

## Section 4: Document Upload + Gesture File Navigation

### Voice-Triggered Upload Flow

User says "upload" (or `/upload`, or taps upload suggestion chip). System opens the file browser overlay. The existing `ImmersiveFileBrowser` extends with two layers:

1. **Virtual layer** (in-app) — folders: "Documents", "Uploads", "Projects", "Recent". Uploaded files land here. Persisted in localStorage (architecture supports server storage later).

2. **Native layer** — swipe down past virtual root enters the native device file system via File System Access API (desktop) or `<input type="file">` fallback (mobile). Same gesture navigation, different data source.

### Tree Spatial Gesture Navigation

Inside the file browser, gestures map to folder navigation:

| Gesture | Action | Visual feedback |
|---------|--------|----------------|
| Swipe up | Parent folder | Folder "lifts" upward with parallax |
| Swipe down | Enter selected folder / open file | Folder "drops" inward, zooms |
| Swipe right | Next sibling | Content slides right-to-left |
| Swipe left | Previous sibling | Content slides left-to-right |
| Hold (700ms+) | Select / confirm | Target glows with brand accent |

### Hand Preference

Settings gets a "Hand preference" toggle: Left or Right. When Left, horizontal gestures mirror (swipe left = next, swipe right = previous). Vertical stays the same. Affects both file browser and general motion gesture system.

### File Type Support

Existing PDF + YouTube ingestion extends via `IngestionAdapter` port. New adapters:

| Format | Method |
|--------|--------|
| `.txt`, `.md` | Plain text, direct ingestion |
| `.docx` | Extract text via mammoth.js |
| `.png`, `.jpg` | OCR via Tesseract.js or vision model |
| `.mp3`, `.wav` | Transcribe via whisper adapter |
| `.mp4` | Extract audio → transcribe, frames → vision |
| `.csv`, `.json` | Structured data, direct ingestion |
| URLs (any) | Fetch + extract readable content |

Each adapter is a separate module. Adding a file type = adding an adapter. No core changes.

### Upload Interaction

- Desktop: drag-and-drop or click to open OS file picker
- Mobile: native file picker
- Selected file gets ingested, added to virtual "Uploads" folder, becomes active source
- Works with voice ("upload" → browser → gesture-navigate → select), gesture (swipe + hold), or keyboard (arrows + enter)

### Component Decomposition

- `GestureFileBrowser` — extends ImmersiveFileBrowser with tree spatial navigation
- `VirtualFileSystem` — in-app folder management, localStorage persistence
- `NativeFileBridge` — File System Access API adapter with fallback
- `IngestionAdapter` (port) — file type ingestion interface
- `IngestionAdapters/*` — one module per file type (pdf, docx, image, audio, video, text, url)
- `useFileNavigation` hook — tree spatial state, hand preference, gesture routing

## Section 5: Error Handling + User Feedback UI

### Feedback Architecture

A `FeedbackBus` port — a typed event emitter. Voice errors, motion failures, upload problems, network issues, incomplete commands — all flow through the same bus. A single `FeedbackOverlay` component renders everything.

### Feedback Types + Visual Treatment

| Type | Visual | Duration | Example |
|------|--------|----------|---------|
| **Success** | Brand accent line flash (2px, `var(--brand)`) at screen edge + subtle haptic | 1.2s | File uploaded, gesture recognized |
| **Info** | Outlined toast, bottom-center, ghost style (2px border, no fill) | 3s | "Listening...", "Processing upload" |
| **Warning** | Outlined toast with `var(--brand-bright)` accent, gentle pulse border | 4s | "Voice unclear, retrying", "Camera permission needed" |
| **Error** | Outlined toast with red accent, shake animation on appear | Until dismissed or 6s | "Upload failed", "Network lost" |
| **Correction** | Inline text morph — recognized text crosses out, correct version fades in | 2s | Voice heard "some rise" → shows "summarize" |

### Brand Compliance

- All feedback: outlined/ghost style, 2px borders, no filled backgrounds on main surface
- Card-style containers only inside modals
- Brand accent line pattern for success states
- Spring easing (`cubic-bezier(0.16, 1, 0.3, 1)`) for all animations
- Reduced-motion support: opacity changes instead of movement when `prefers-reduced-motion`

### Voice/Motion-Specific Feedback

- **Incomplete voice**: speech detected but no match and not a question → Correction feedback: what was heard, then fade to "I didn't catch that"
- **Mic error**: `SpeechRecognition` errors → outlined toast with retry + quick toggle shows dimmed
- **Camera error**: permission denied → toast with "Enable in settings" action chip
- **Gesture ambiguous**: motion energy between thresholds → brief pulse on gesture layer: "I sensed movement but couldn't classify it"
- **Upload incomplete**: outlined progress bar (brand accent fill) showing stages: reading → parsing → ready. Failure → error toast with stage name

### Non-Verbal Feedback

User can give feedback without words:
- Head shake (motion detected) on error toast → dismiss it
- Nod (motion detected) on suggestion chip → execute it
- Both map to same `FeedbackBus` events as taps/voice

### Accessibility

- All toasts: `role="alert"` or `role="status"` with `aria-live`
- Error toasts keyboard-focusable, dismissible with Escape
- Color never the only signal — each type has distinct icon (outlined) and motion pattern
- Screen readers announce feedback text

### Component Decomposition

- `FeedbackBus` (port) — typed event emitter interface
- `FeedbackBusAdapter` — in-memory implementation
- `FeedbackOverlay` — renders all feedback types
- `FeedbackToast` — individual toast component (success, info, warning, error, correction)
- `useFeedback` hook — connects bus to React components

## Section 6: Language-Specific Voice Commands + Settings + Testing

### Voice Command Dictionary

A `CommandDictionary` port in `packages/core/src/domain/` mapping actions to language-specific trigger words:

| Action | English | French |
|--------|---------|--------|
| Upload | "upload", "load file" | "téléverse", "charge le fichier" |
| Summarize | "summarize", "summary" | "résume", "résumé" |
| Back | "back", "go back" | "retour", "reviens" |
| Stop | "stop", "enough" | "arrête", "stop" |
| Search | "search", "find" | "cherche", "trouve" |
| Open files | "open files", "files" | "ouvre les fichiers", "fichiers" |
| Next | "next", "forward" | "suivant", "prochain" |
| Cancel | "cancel", "never mind" | "annule", "laisse faire" |
| YouTube | "youtube", "video" | "youtube", "vidéo" |
| Settings | "settings", "menu" | "paramètres", "menu" |

Dictionary is data, not code. Adding a language = adding a new entry. Existing fuzzy matching (1 edit distance) and shield rules (negations, question openers) apply on top.

### Settings Menu Reorganization

Card-style sections following brand modal pattern:

1. **General** — Language, Theme, Assistant name
2. **Voice & Audio** — Voice output toggle, Voice speed, Custom triggers
3. **Camera & Motion** — Video overlay toggle, Motion detection toggle, Hand preference (L/R)
4. **Keyboard** — Enable keyboard input toggle (off by default)
5. **Non-Verbal Tracking** — Tracking toggle, View session log
6. **Files** — Default upload folder, Supported formats info
7. **Device** — Bluetooth, Internet endpoint (existing DeviceConnect)
8. **Session** — Reset, Clear conversation
9. **About** — Account info, Version

Each card: brand accent line on top, spring-easing hover animation, staggered reveal (40ms delays). All toggles are outlined switches, no filled pills.

### Testing Strategy

Every new component tested at four levels:

| Level | What | Where |
|-------|------|-------|
| **Unit** | Domain logic: command dictionary matching, gesture-to-folder mapping, suggestion engine rules, feedback bus routing, file type adapter selection | `packages/core/src/domain/*.test.ts` |
| **Contract** | Port interfaces: NonVerbalTracker, FeedbackBus, IngestionAdapter, CommandDictionary — verify adapters satisfy the contract | `packages/core/src/domain/*.contract.test.ts` |
| **Component** | React components: QuickToggle state, VideoOverlay opacity, KeyboardMode slash commands, FeedbackOverlay types, GestureFileBrowser navigation | `apps/web/app/components/*.test.tsx` |
| **BDD** | End-to-end user journeys in Gherkin | `features/*.feature` |

### BDD Scenarios

- `keyboard-fallback.feature` — enable in settings, slash commands, text send, coexists with voice
- `video-overlay.feature` — toggle on/off, opacity layer, camera permission flow
- `non-verbal-tracking.feature` — gesture logged, mood color changes, session log viewable
- `gesture-file-navigation.feature` — tree spatial nav, hand preference mirroring, virtual/native layer transition
- `document-upload.feature` — voice trigger, file type ingestion, progress feedback, error recovery
- `feedback-ui.feature` — error toast, success flash, incomplete voice correction, reduced-motion support
- `language-commands.feature` — French commands match, cross-language fuzzy, shield rules in both languages

### Definition of Done (per feature)

1. Unit tests pass (domain logic)
2. Contract tests pass (port interfaces)
3. Component tests pass (rendering + interaction)
4. BDD scenarios pass (Playwright)
5. Visual check via browser automation (brand compliance, animation timing)
6. Reduced-motion verified
7. No regressions in existing 1079 tests

## Architecture: Hook Extraction (Prerequisite)

Before building new features, `Workspace.tsx` (1835 lines) decomposes into focused hooks:

| Hook | Responsibility | Extracted from |
|------|---------------|----------------|
| `useVoice` | Speech recognition lifecycle, echo guard, quiet limit | VoiceActions logic |
| `useMotion` | Camera lifecycle, gesture recognition, frame processing | MotionActions logic |
| `useConversation` | Conversation reducer, message sending, chat socket | Workspace state |
| `useFileNavigation` | File browser state, folder tree, hand preference | Workspace + ImmersiveFileBrowser |
| `useFeedback` | Feedback bus connection, toast lifecycle | New |
| `useNonVerbalTracking` | Tracker lifecycle, event bus, session log | New |
| `useKeyboardMode` | Keyboard state, slash command routing | New |
| `useSuggestions` | Context-aware action suggestions | New |

After extraction, `Workspace.tsx` drops to ~400 lines of orchestration — composing hooks and rendering child components.
