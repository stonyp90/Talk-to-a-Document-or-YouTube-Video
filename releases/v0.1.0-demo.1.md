# Ursly v0.1.0-demo.1 — Local demo preview

This prerelease contains the current Android application tested against a local Docker backend. **It is not a production release or a standalone online demo.** OpenAI is not configured and live YouTube transcript retrieval is blocked on the tested network.

## Download

- **`ursly-v0.1.0-demo.1-android-arm64-local.apk`** — Android ARM64, Android 7.0/API 24 or later. Tested on an ARM64 Android 15 emulator. Package `com.talktosource.demo`, native version `0.1.0` (build `1`). Requires the local backend below. Physical phones have not been certified.
- **`SHA256SUMS.txt`** — asset integrity checksums.
- **`BUILD-MANIFEST.json`** — APK hash, source fingerprints, release commit and validation scope.
- **`INSTALL.md`** — local setup and installation instructions.

The APK includes the current Ursly interface, English/French switching, PDF ingestion, text chat, and voice session controls. AI answers and audio are simulated with the default backend configuration. No OpenAI or AWS permanent credential is embedded in the app.

## Run the demo

From the release source checkout, with Docker Desktop running:

```bash
cp .env.example .env.local
WEB_PORT=3100 APP_ORIGIN=http://localhost:3100 docker compose --env-file .env.local up -d --build --wait web
```

Choose an ARM64 Android emulator. With Android platform-tools available:

```bash
adb devices
adb -s <device-id> reverse tcp:3100 tcp:3100
adb -s <device-id> reverse tcp:9002 tcp:9002
adb -s <device-id> install -r ursly-v0.1.0-demo.1-android-arm64-local.apk
adb -s <device-id> shell am start -n com.talktosource.demo/.MainActivity
```

The APK targets `http://localhost:3100`; signed PDF uploads use `http://localhost:9002`. Keep Docker and both port forwards running. Recreate port forwards after reconnecting the emulator/device. Installation updates an existing copy signed with the same Expo project key without requiring a data reset. A signature mismatch requires investigation; do not erase user data automatically.

The local native network policy permits HTTP only for `localhost` and `127.0.0.1`; other destinations require HTTPS. This policy was applied to the generated Android manifest/resources for this local build. Its XML and the build details are recorded in the manifest attached to the release.

On macOS/Linux, verify the download:

```bash
shasum -a 256 -c SHA256SUMS.txt
```

## Validation performed

- Gradle release build completed; APK signature and installed APK SHA-256 verified.
- Android UI: English/French switching verified; text reply, simulated session start, mute and stop passed against the local backend.
- iOS Simulator: current local build and the same text/session controls verified separately. No physical-iPhone IPA is included.
- Real PDF upload, extraction and consumed-upload replay rejection passed.
- 18 browser checks passed in the demo readiness run.
- Source secret scan passed; server secrets remain outside the repository and client configuration.

## Known release blockers

- No configured OpenAI API key: live answers, real ephemeral session issuance, quota, microphone/audio playback and interruption remain unverified.
- Live YouTube retrieval returned HTTP 403 on both test videos. Simulated transcripts do not establish real YouTube support.
- Public API authentication and per-user quotas are required before public deployment.
- Mobile dependency audit still reports 19 affected entries, including 9 high-severity entries; see `SECURITY-REVIEW.md`.
- Public backend readiness, remote CI acceptance and physical-device certification are not asserted by this prerelease.
- The APK is built from the current working source snapshot. The manifest fingerprints identify its mobile sources; its local native network override is documented separately. The original Git HEAD alone did not identify this snapshot.

See `DEMO-READINESS.md`, `SECURITY-REVIEW.md` and the root `README.md` for configuration, limitations and next validation steps. `npm run demo:check` deliberately fails while the backend remains in simulated mode.
